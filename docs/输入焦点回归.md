# 编辑窗口输入焦点回归

## 问题与原因

旧版打开流程纸编辑器后，在阶段输入框输入 `先做第1`。跨过后台7秒刷新周期后，焦点自动回到标题；继续按 `2` 会把标题改为 `标题不应被改动2`。

原因是 Modal 的焦点 effect 依赖 `onClose`，而墙面的定时同步会重新创建回调，触发 effect 清理、恢复旧焦点并再次聚焦第一个输入框。数字只是恰好在焦点被抢走后输入的字符。

## 修复

- 弹窗首次挂载时设置初始焦点；若用户已经在弹窗内操作，不再主动移动焦点。
- 用 ref 读取最新关闭回调，让关闭行为仍能判断保存状态，而不会重启焦点生命周期。
- 保留 Tab 焦点限制、Escape 关闭及真正卸载时恢复原焦点。
- 没有改变数据结构、阶段保存或线上用户数据。

## 回归步骤

1. 打开新增流程纸，填写标题 `标题保持不变`。
2. 第一阶段输入 `12345`，把光标放在 `12|345`。
3. 跨过至少两次7秒同步周期，不重新点击或聚焦输入框。
4. 检查焦点仍为「第1阶段」，selectionStart 仍为2。
5. 使用当前焦点直接按 `9`，应得到 `129345`，标题保持不变。
6. 在393×852手机尺寸下，对第二阶段重复等待、数字输入与中间插入检查。
7. 用 Escape 关闭、重新打开，检查首次聚焦和键盘 Tab 导航仍有效。

必须使用当前焦点发送后续按键，不能每次输入都用 fill/type 自动重新聚焦目标框，否则会掩盖这个问题。
