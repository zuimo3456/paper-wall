# 纸上：独立部署

这是一个无登录、单人共用一面墙的版本。前端、API、SQLite 数据库在同一个服务内运行；无需 ChatGPT、Cloudflare 或外部数据库。Docker 镜像只含程序，不含原站的私人事项。

## 直接运行

安装 Node.js 24 LTS，解压部署包，在该目录运行 `node server.mjs`，打开 `http://localhost:8080`。默认监听所有网卡；同一 Wi-Fi 手机可访问电脑局域网 IP 的 8080 端口（需允许防火墙入站）。电脑关机后该方式停止服务，不是公网托管。

数据默认保存在 `data/wall.sqlite`。可用 `PORT`、`HOST`、`DATA_DIR` 环境变量调整；不要把数据目录放进 GitHub 或公开静态资源目录。

## 容器平台

在部署包目录构建 `docker build -t paper-wall .`，本机用 `docker compose up -d`。国内容器平台同样可运行该镜像，服务端口 8080，健康检查 `/healthz`，**必须把持久卷挂到 `/app/data`**；使用一个副本，不要让两个容器共享写同一个 SQLite 文件。挂载目录需可由镜像内 `node` 用户（UID 1000）写入。

选平台前核对：国内手机关闭代理能否打开分配的网址、试用到期费用、域名使用限制、存储是否持久化。平台赠送额度不等于永久免费；Sealos 官方服务条款将自动分配域名限定为开发、调试、临时访问，长期使用要另行解决正式域名。大陆自定义域名涉及备案，境外节点需手机实测线路。

## 迁移数据

在旧网站归档盒点击导出备份，把 JSON 保存在本地。停止新服务后运行 `node server.mjs --import 备份.json`，再启动。导入保留 ID 和版本号，相同 ID 跳过，避免覆盖新端数据。迁移完成前不要交替编辑新旧网站，它们是两个独立数据库。

服务器备份运行 `node server.mjs --export 备份.json`；同时定期在网页导出。运行中不要只复制主 SQLite 文件而漏掉 WAL。

## GitHub Pages

GitHub Pages 只能托管静态前端，不能运行此服务或 SQLite。若需要 `.github.io` 入口，仍须部署后端并配置 HTTPS；构建前端时设置 `VITE_WALL_API_BASE=https://后端域名`，后端设置 `ALLOWED_ORIGINS=https://你的用户名.github.io`，项目页设置 `VITE_BASE_PATH=/仓库名/`，再运行 `node scripts/build-portable.mjs`。上传生成的 `public/` 到 Pages，不要上传数据库、数据备份或密钥。

若只放静态前端且不部署后端，不能实现手机和电脑自动同步。当前推荐完整服务放在同一托管平台，GitHub 用于保存源代码。部署后验收：手机关闭代理新增、电脑看到、电脑完成、手机刷新看到、重启服务器后数据仍在。

仓库已提供 `.github/workflows/pages.yml`，手动触发发布。使用时在仓库 Settings → Pages 中选择 GitHub Actions，并在 Settings → Secrets and variables → Actions → Variables 添加 `WALL_API_BASE`，值为已部署后端的 HTTPS 源站，例如 `https://api.example.com`。后端需放行该 Pages 源站的 CORS。工作流会检查后端配置存在，不会把一个没有同步服务的页面当作成品发布。
